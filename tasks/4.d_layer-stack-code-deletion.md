# Phase 4d — Layer-stack code deletion

## Status

**Runtime disable: done.** Every layer-stack-touching path is
already inert as a side-effect of Phases 4a/4b/4c: compaction loop
never spawns, `layer.put_batch` is never called, `InMemoryLayer` is
never created, layer reads are never dispatched, disk-usage eviction
returns `None` (disabled by config), secondary downloader/uploader
sit idle (no secondary tenants), heatmaps are empty, GC is a no-op.

**Code deletion: in progress.** Incremental, compile-driven, one
module per commit. ~24.5K LOC removed so far.

- Full `remote_timeline_client/` unwind (~2800 LOC across 5 files,
  ~25 internal call sites tied to `Timeline.remote_client`,
  `index_part.json` upload path, `delete.rs`). Plan inventoried
  below.
- `storage_layer/layer_name.rs` (387 LOC, only droppable after RTC's
  `index.rs` no longer references `LayerName`).

### Proposed replacement: `TimelineRemoteState`

```rust
pub struct TimelineRemoteState {
    pub rc_lsn: Arc<utils::lsn::AtomicLsn>,
    pub archived: AtomicBool,
    pub invisible: AtomicBool,
    pub deleting: AtomicBool,
    pub gc_blocking_reasons: Mutex<HashSet<GcBlockingReason>>,
}
```

Three atomic bools + an LSN slot + a small reason set. ~30 LOC
total. Lives on `Timeline` replacing the `Arc<RemoteTimelineClient>`.

### Suggested commit sequence

1. **Add `TimelineRemoteState`** alongside `RemoteTimelineClient`,
   wire it into `Timeline::new`, populate it from RTC state during
   construction. Don't delete RTC yet.
2. **Switch callers of LIVE methods** (rcLsn, archived, invisible,
   deleting, ancestor-lsn, gc-block reasons) to use
   `TimelineRemoteState`. RTC stays as the impl of DEAD methods.
3. **Replace `delete_all`** with the direct-YB-DELETE implementation
   in `delete.rs`; remove the RTC call.
4. **Delete each DEAD method** from RTC + remove its single call
   site. Most are 1-liners at the call site (e.g. `wait_completion`
   becomes nothing; `shutdown` becomes a no-op).
5. **Delete `RemoteTimelineClient` + `download.rs` + `index.rs` +
   `manifest.rs` + `upload.rs`** once the field on `Timeline` is
   gone. Should compile cleanly; `cargo check` is the verifier.
6. **Delete `storage_layer/layer_name.rs`** (chunk 2) — RTC's
   `index.rs` was the last consumer.

Steps 1–2 are the riskiest (touch the LIVE state machine);
3–6 are mechanical compile-driven removals.

The stubbed admin handlers (`timeline_detach_ancestor_handler`,
`deletion_queue_flush`, `timeline_preserve_initdb_handler`) stay —
storage_ctl RPC paths intentionally hit them and the typed
"not supported" error is better UX than a 404.
