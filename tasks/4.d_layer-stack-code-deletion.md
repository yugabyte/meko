# Phase 4d — Layer-stack code deletion

## Status

**Runtime disable: done.** Every layer-stack-touching path is
already inert as a side-effect of Phases 4a/4b/4c: compaction loop
never spawns, `layer.put_batch` is never called, `InMemoryLayer` is
never created, layer reads are never dispatched, disk-usage eviction
returns `None` (disabled by config), secondary downloader/uploader
sit idle (no secondary tenants), heatmaps are empty, GC is a no-op.

**Code deletion: in progress.** Incremental, compile-driven, one
module per commit. ~24.5K LOC removed so far.

## Remaining

Each its own session:

- Full `remote_timeline_client/` unwind (~2800 LOC across 5 files,
  ~25 internal call sites tied to `Timeline.remote_client`,
  `index_part.json` upload path, `delete.rs`).
- `storage_layer/layer_name.rs` (387 LOC, only droppable after RTC's
  `index.rs` no longer references `LayerName`).
- `IoConcurrency` / `ValuesReconstructState` pass-through markers
  threaded through ~20 function signatures (basebackup,
  pgdatadir_mapping, page_service, walingest, http routes) —
  mechanical but every getpage path touches them.

The stubbed admin handlers (`timeline_detach_ancestor_handler`,
`deletion_queue_flush`, `timeline_preserve_initdb_handler`) stay —
storage_ctl RPC paths intentionally hit them and the typed
"not supported" error is better UX than a 404.
