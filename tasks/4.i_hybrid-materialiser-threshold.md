# Phase 4i — Hybrid materialiser threshold (count OR combined-delta-size)

`MaterializerHandle` carries `count_limit` AND `payload_bytes_limit`;
per-key `DeltaTally { count, payload_bytes }` accumulates on each
non-anchor `put` and resets on `is_image` / `will_init`. Whichever
threshold lands first dispatches.

- Either zero disables that trigger.
- Both zero disables the materialiser.

## Defaults

- `image_chain_limit` 10 → 20.
- New `image_chain_payload_bytes_limit` = 4096 (4 KiB).

Catches small-delta accumulation (count) and large-delta bursts
(bytes — a single near-full-page rewrite already represents 8 KB of
walredo work to apply on every subsequent read).

Tunable per-deployment via `[yb_page_writer]` in `pageserver.toml`.
Existing 25 unit tests pass.

Microbench tuning across the (count × bytes) matrix deferred to
`4.j` until we have a workload that exercises both regimes.
