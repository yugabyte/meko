# Phase 4e — Write-path hardening + perf tuning

- Chunked INSERTs in `put_pages` / `put_slru_pages` / `put_meta` to
  stay under tokio-postgres's 65535-parameter / "value too large to
  transmit" caps (500 / 500 / 2000 rows per chunk).
- `PageWriter::flush()` no longer `mem::take`s the buffer — clones a
  snapshot under the lock, drops the lock, INSERTs, then
  `drain(0..N)` under the lock on success. Fixes a race where a
  concurrent walreceiver `read_chain` on a rel-size sentinel saw
  `MissingKey` while the buffer was "in transit" to YB, corrupting
  walingest.
- Parallel chunk dispatch via `buffer_unordered(4 / 2 / 3)`.
- `yb_enable_upsert_mode = true` set per-connection so chunk retries
  can't PK-conflict.
- `state: Mutex` → `RwLock` so concurrent reads parallelise.
- Default `flush_size_bytes` lowered from 100 MiB → 25 MiB to bound
  `wait_lsn` tail latency after bulk inserts.

## End-to-end perf workload (200k rows, 50 MB shared_buffers)

- UPDATE 19k rows: 20.4 s → 2.6 s
- CREATE TABLE AS update_ids: 9.0 s → 0.55 s
- Zero "slow wait_lsn" warnings.
