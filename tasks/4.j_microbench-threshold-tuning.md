# Phase 4j — Microbench tuning matrix for 4i thresholds

Pick a workload that exercises both axes of `4.i`:

- Small-delta accumulation (lots of
  `ClearVisibilityMapFlags`/visibility-map updates).
- Large-delta bursts (heap rewrites, near-full pages).

## Sweep

`image_chain_limit` ∈ {10, 20, 40} × `image_chain_payload_bytes_limit`
∈ {2 KiB, 4 KiB, 8 KiB, 0 (disabled)}.

## Track

- Materialiser firings per workload.
- Read-side walredo cost on chains.
- INSERT throughput in `pageserver.pages`.

Today's defaults (20 / 4 KiB) are intuition-based. Likely outcome:
tune separately per workload-class via tenant config rather than a
single global default.
