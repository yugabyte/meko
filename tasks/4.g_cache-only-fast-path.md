# Phase 4g — Cache-only read fast path + materialiser batched INSERT + per-key completeness

`UnifiedPages` gains `KeyState { chain, evicted_below }`; reads call
`lookup_chain_if_complete` first (anchor present + `anchor_lsn >
evicted_below` → serve from RAM, skip YB).

`PageWriter::scan_range` dispatches the single-key range (the
`getPage` hot path) to `read_chain` so it gets the same fast path.

The materialiser worker drains up to 64 jobs per iteration,
walredoes each, dumps all resulting images in one parameterised
batched INSERT, then installs each into cache.

## Results

- Slow `scan_range` log lines on a 20k-UPDATE workload drop
  **8397 → 213** (40×).
- Microbench best-of-3 vs pre-3e/3f baseline:
  - `count_heap`: 5.2 s → 1.1 s (4.9×)
  - `seqscan`: 5.5 s → 1.1 s (5.0×)
  - `pk_point_lookup_10k`: 117 s → 21 s (5.5×)
  - `idx_range_scan`: 243 ms → 26 ms (9.3×)
