# sha256 of every external file amp's builds download, one `<sha256>  <url>`
# line per URL. scripts/safe_curl.sh verifies each download against this file,
# so a file that changes behind a URL we already pinned — a compromised
# mirror, a re-tagged release, a swapped object — fails the build instead of
# being installed.
#
# The rules, which follow yugabyte-db-thirdparty's thirdparty_src_checksums.txt:
#   * every download is pinned here, and only here;
#   * a URL with no line fails the build, printing the line to add — so adding a
#     download means adding its checksum, after confirming the file is the one
#     you meant (`scripts/safe_curl.sh add <url>` fetches it and appends the line);
#   * a pin is never edited in place: a new version is a new URL and a new line,
#     and the old line goes when nothing fetches it any more;
#   * `scripts/safe_curl.sh check` validates the file: 64 lowercase hex, an https
#     URL, each URL once.
#
# A URL computed at build time (a version ARG, `uname -m`) is pinned for each
# value it takes, so every architecture a build supports has its own line.
# Floating URLs ("latest", unversioned dist paths) cannot be pinned and are not
# used.
#
# Not covered, deliberately:
#   * deploy/voyager/Dockerfile clones yb-voyager from a branch (VOYAGER_COMMIT
#     pins and checks it when set; its default is "unpinned"), and the voyager
#     installer then downloads its own dependencies. That image tracks a branch
#     on purpose; it is not an amp build input.
#   * integrity with a chain of its own: apt (signed repositories), the Rust
#     toolchain rustup installs (its dist manifest), cargo install --locked.
#
# The build-tools pins take effect when the next build-tools tag is published:
# consumers build FROM an immutable amp-build-tools:<tag>, published from the
# recipe of its day (deploy/build-tools/build.sh).
